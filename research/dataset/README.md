# Decentralized Hiking AI — research data release

Collected 2026-10-14 for a Sri Lankan university prototype that recommends offline resources before a hiker enters weak connectivity. This is a PARTIAL traceable data release, not a complete training dataset. No model trained and no training labels created.

## Areas and supplied trail file
Ten provisional AOIs: Knuckles (primary), Horton Plains, Sri Pada/Adam's Peak, Ella, Riverston, Meemure, Sinharaja, Pidurangala/Sigiriya, Namunukula and Haputale. See `metadata/study_areas.csv` for coordinates. These rectangles are investigator-selected collection extents, not authoritative park boundaries. Some overlap. The user's existing `knuckles_trails.geojson` was not supplied and has not been validated or replaced. New files explicitly say `candidate_paths`.

## What files mean
`raw/trails`: unchanged dated Geofabrik country PBF, checksum, separate regional extracts, hiking-relation metadata, saved Overpass queries and any successful raw responses. Country PBF is the smallest available Geofabrik subregion and supports reproducible fallback extraction. `processed/trails/*_candidate_paths.geojson` uses the dated PBF consistently. Raw regional GeoJSON extracts are derived subsets; the original bytes are in the PBF. Overpass responses represent different snapshots and must not be merged blindly.
`raw/weather`: original Open-Meteo API JSON for 2021–2025. `processed/weather`: hourly CSV with requested point and returned weather-cell coordinates, API downscaling elevation and explicit UTC timestamps. Five Knuckles points and one point per remaining AOI, selected provisionally across the collection boxes rather than from verified routes. Refine them using validated trail clusters and elevation strata. These are not 14 independent weather stations; shared cells and ERA5 forcing create dependence. Model explicitly selected: `era5_seamless`, combining ERA5-Land temperature/humidity with ERA5 atmospheric inputs. Mountain microclimate and rainfall extremes remain unresolved. Visibility is unavailable and absent, never invented.
`raw/elevation`: four unchanged Copernicus GLO-30 2021-release one-degree GeoTIFFs. This is a DSM (vegetation/building surface), not bare-earth ground truth. Horizontal WGS84, heights in metres relative to EGM2008. `processed/elevation`: profiles sampled at <=60 m with nearest raster elevation and a central-difference 3x3 local slope in degrees using geodesic pixel spacing. Gain/loss are sums along OSM node order; direction is arbitrary, no noise smoothing. Tree canopy and raster noise bias gain/loss, so compare 30/60/90 m sampling and smoothing before reporting route ascent. Rows at tile edges/nodata remain missing.
`raw/emergency`: factual national contacts and OSM mapped facilities. OSM facilities need verification of operation, hours, potable water and rescue capability. OSM spring is not potable-water evidence. Facility ways may be lines, not building polygons; use proper geometry reconstruction if needed. Emergency numbers do not enable calls without a reachable network.
`raw/hazards`, `raw/connectivity`, `raw/safety_sources`: source catalogues; downloaded public warning RSS is a current snapshot, not historical hazard observations. Copyright-restricted PDFs and operator coverage maps are linked rather than bundled. No spatial landslide/flood classes, measured signal values, or independently validated targets are supplied.

## Collection and provenance
See `metadata/dataset_sources.csv`, `licenses.csv`, `download_log.jsonl` (exact request URL, UTC access time, success/failure, bytes and SHA256), and `file_manifest.csv` for produced-file checksums. Source catalogues distinguish metadata-only sources from downloads. `data_dictionary.csv` and `final_table_design.csv` describe meanings, units and proposed joins. `processing_manifest.csv` maps processed outputs to raw inputs and algorithms.
OSM candidates include path/footway/track/steps/bridleway plus hiking-relation member ways. Preserve all tags, including name, sac_scale, incline, trail_visibility, foot, access and surface. Never infer verified hiking status from highway=path. Review private/no-access tags, official permits, route continuity and local guide knowledge. Hiking route relations may contain mixed ways, roles and missing members. PBF relation metadata is retained but complete ordered routes are not assembled.

## Joins and final table
Use stable typed OSM IDs (`way/123`) rather than names. Deduplicate shared ways across overlapping AOIs. Elevation profiles join by trail_id and point_index; weather joins use justified cell selection/interpolation and timestamps, preserving original cell ID, request coordinates and distance. Do not duplicate an hourly value as independent measurements at many nearby points. Transform to EPSG:32644 for metric spatial operations, or use WGS84 geodesics as these scripts do; do not measure distance in degrees.
Licensed hazards later join through point-in-polygon/raster sampling at valid dates with legend and resolution intact. Connectivity later uses operator/technology-aware coverage membership or estimated cell distance, with age and sampling uncertainty. Nearest mapped facility distance is a remoteness proxy, not evacuation time. Water points provide mapped proximity, not flow reliability or drinkability. Leave unavailable features and labels NULL and add missingness/provenance indicators. No final feature/label table has been fabricated.

## Reproduce
Python 3.11+; install `numpy`, `rasterio`, `pyproj`, `osmium` from `scripts/requirements.txt`. From this directory run `python scripts/download_weather.py`, `python scripts/download_elevation.py`, `python scripts/download_trails.py`, and `python scripts/download_reference.py`. The dated PBF URL is recorded in the log; download it to `raw/trails/sri-lanka-261012.osm.pbf` if reproducing from an empty folder. Run `python scripts/download_osm_snapshot.py`, `python scripts/extract_osm.py` and `python scripts/extract_connectivity_proxy.py`, then `python scripts/process_elevation.py`, `python scripts/build_documentation.py`, then `python scripts/prepare_dataset.py`. Existing raw files are overwritten by download scripts; run into a copied versioned directory to preserve this release. Fixed dates reproduce the requested interval, but provider reprocessing can change values; bundled checksums identify this exact release.
